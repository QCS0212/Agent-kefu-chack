# 项目背景：客服回复幻觉检测

## 1. 项目来源

本项目对应任务「0110 · 客服回复幻觉检测」。团队的智能客服系统偶尔会在回复用户时编造不存在的优惠政策、提供错误退货地址、杜撰产品参数，或声称完成实际上无法执行的操作。业务方需要一个工具，批量发现这些回复中的事实问题，并解释判断依据。

本阶段以提供的 20 条样本为验证对象，建设可运行、可评估、可解释的检测原型。当前没有接入线上客服系统，也不代表已部署生产质检服务。

## 2. 业务问题与价值

客服回复即使语言流畅、语气肯定，也可能缺乏事实依据。用户据此购买、寄回商品或等待退款，会承担错误决策和办理延误的风险；业务团队则可能面临投诉、额外售后成本和信任损失。

本项目重点解决三个问题：

1. **发现问题**：识别回复与业务知识冲突、无依据断言、虚假执行以及误导性遗漏。
2. **解释问题**：指出具体错误声明、对应知识依据、分类和严重程度，便于人工复核。
3. **验证效果**：与人工标签独立对照，公开漏检、误报及边界案例，避免仅凭演示判断工具有效。

预期使用者包括客服质检人员、业务运营人员及负责模型和提示词维护的工程师。工具提供复核依据，不自行修改订单、发放优惠券或作出退款操作。

## 3. 已有数据

| 文件 | 内容 | 用途 |
|---|---|---|
| `data/task4_replies.json` | 20 条客服回复，每条包含 `id`、`user_question`、`system_reply`、`knowledge_base` | 检测输入与事实核验依据 |
| `data/task4_ground_truth.json` | 每条的人工幻觉标签、类型和说明 | 检测完成后的独立评估 |

每条样本已附带知识依据，因此首版不需要额外建设知识检索平台或向量数据库。部分知识依据明确说明系统没有查询或修改接口，可用于识别能力越界。

当前人工标签中，18 条为幻觉、2 条为正常。这是数据分布，不是工具运行结果。样本量小且类别不均衡，不能据此宣称具备生产环境泛化能力。人工标签已在方案讨论阶段被查看，后续评估属于给定样本验证，不是盲测。

## 4. 任务目标

按照原始任务要求，项目需要完成：

1. 自行定义幻觉分类体系，说明判断边界和严重程度。
2. 实现自动化检测，逐条标注 20 条回复，提供判断理由。
3. 使用人工标签计算检出率，并明确哪些案例漏检、哪些误报。
4. 分析错误原因和容易误判的边界。
5. 在 README 中说明分类、方法、实测结果及 AI 工具使用情况。

不预设必须达到 100% 检出率；评估真实性与错误解释是验收的重要部分。

## 5. 检测范围与判断口径

初始分类包括政策与优惠错误、产品事实错误、业务信息编造、能力越界与虚假执行、安全提示失真、条件遗漏与过度概括。具体分类 key、结果字段和开发约定见 `AGENTS.md` 与 `app/schema.py`。

核验时区分以下情况：

- **与知识冲突**：回复中的参数、政策或其他事实与所给依据不一致。
- **无依据断言**：材料没有支持某个业务事实，回复却作出确定性断言。可按本任务口径标为幻觉，但不能表述为已证明现实中该事实为假。
- **证据不足**：无法形成可靠判断，需要进一步核验。
- **普通省略**：仅列举部分正确内容，且没有改变结论，不自动算幻觉。
- **误导性遗漏**：省略重要条件使结论或建议失真，属于检测范围。

技术调用失败与业务上的证据不足不同，必须分别记录。不能把模型超时或解析失败当成正常回复。

## 6. 实现方向

首版采用 Python CLI、检测器接口、独立评估程序和静态 HTML 报告：

```text
回复、用户问题与对应知识依据
    → 事实声明核验
    → 结构化判断、分类、严重程度与证据
    → 程序校验并保存预测
    → 独立对照人工标签
    → 指标、错例与报告
```

正式检测计划接入真实 LLM API，mock 用于无需密钥的流程演示和开发测试。具体提供商与模型尚待确定，真实调用能力不能视为已经完成。

检测器不能读取人工标签，也不能按样本 ID 硬编码答案。mock 结果不能作为真实模型检出率。无需在初始范围内引入多 Agent、自主规划、完整后台或生产系统集成。

## 7. 评估重点与已知难点

正式评估应展示 TP、FP、FN、TN、Precision、Recall、F1、Accuracy，并列出误报、漏检和待核验案例。仅明确判为幻觉视为检出，待核验的真实幻觉仍计入漏检。

如果把所有样本都判成幻觉，当前数据会得到 100% 召回率和 90% 准确率，因此单个高指标不足以证明检测有效。应同时解释正常样本上的表现以及统计范围。

以下是从材料中识别的预期难点，不是实测错误：

- h09、h15：区分「未提供依据」和「明确否定」，识别无依据的肯定回答。
- h16：色差提醒与知识一致，但「都是实物拍摄」缺少直接支持，可能产生检测口径与人工标签分歧。
- h12、h20：区分不影响结论的部分列举与影响选择的关键条件遗漏。
- h04、h06：一条回复包含多个事实，部分正确不能掩盖其他错误。

如后续调整提示词，应保留首次与迭代后的结果，说明它们来自同一批已知样本，不将调优成绩包装成独立测试成绩。

## 9. 当前阶段与下一步

截至本文创建时，项目处于基础骨架阶段：已有输入校验、mock 检测器、独立评估模块、JSON 输出、HTML 基础报告及单元测试。mock 对 20 条样本返回待核验，不提供正式模型指标。

后续按以下顺序推进：

2. 确定 API 提供商、模型与本地密钥配置，接入真实检测。
3. 批量运行，独立评估并分析实际错例。
4. 完善证据展示、README、真实截图及最终交付。
